MULTIWAY SEARCH TREES · 01

B-trees

A B-tree keeps multiple sorted keys in each node. One comparison inside a node chooses which child interval can contain the target.

Invariant

For a minimum degree t ≥ 2: each non-root node has t−1 to 2t−1 keys; internal nodes with k keys have k+1 children. All leaves share a depth.

Why it stays shallow

Each node branches to many children. Splitting a full child promotes its median, growing the tree upward only when the root splits.

Where it fits

Large ordered indexes on storage systems, where reducing page reads matters. Range scans are supported by in-order traversal.

MULTIWAY SEARCH TREES · 02

2–3 trees

A 2–3 tree is a balanced search tree where each internal node is either a 2-node or a 3-node. It is a special B-tree with at most two keys per node.

2-node

One key, two child intervals: keys smaller than the separator and keys larger than it.

3-node

Two ordered keys, three child intervals: below, between, and above those keys.

Balance rule

Every leaf is at the same depth. A split may promote a key and propagate upward; a root split adds one level.

TRY IT

Watch 2–3 node splits

Each node holds one or two keys. Insert the third key into a full node and its middle key moves up.

● INTERACTIVE
Insert: 10, 20, 30, 40, 50, 60, 70. Notice every leaf stays level.
Search path: At each node, compare against its one or two keys and follow the matching interval. A tree with n keys has height Θ(log n); search and insertion take O(log n) node visits.
MULTIWAY SEARCH TREES · 03

B* trees

A B* tree is a B-tree variant that delays splitting a full node. It first tries to redistribute keys with a sibling; if both are full, it splits two nodes into three.

Higher occupancy

With maximum m children, non-root nodes are generally kept at least about two-thirds full, compared with the B-tree's one-half minimum.

First choice: redistribute

If a neighboring sibling has room, move a parent separator and keys among the sibling and the overflowing node.

Then: 2-to-3 split

When the sibling is also full, redistribute the combined keys and separators across three nodes, promoting two separators.

MULTIWAY SEARCH TREES · 04

B+ trees

Internal nodes guide search; all records (or record pointers) live in linked leaves. This makes ordered range scans especially efficient.

Internal nodes

Contain separator keys and child pointers. A separator directs the search; it is not the only place a data record may be stored.

Linked leaves

Leaf pages contain the actual keys and point to the next leaf. After locating the first key, a range query walks adjacent leaves.

Compared with B-tree

B-trees can store records in internal and leaf nodes. B+ trees concentrate records in leaves, often increasing internal fanout and simplifying scans.

TRY IT

B+ tree insertion and range scan

Insert keys, then scan an inclusive range across the linked leaf level.

● INTERACTIVE
Insert: 8, 3, 15, 1, 6, 10, 20, 4, 7, 12. Then try range 4 to 12.
Range-query idea: descend once to the leaf containing the lower bound (O(log n)), then scan sequentially until the upper bound (O(k) for k reported keys): O(log n + k).
HEAPS · 01

Binary heaps

A binary heap is a complete binary tree stored compactly in an array. In a min-heap, each parent key is no greater than its children.

Shape property

All levels are full except possibly the last, which fills from left to right. This lets an array represent the tree without pointers.

Heap-order property

For a min-heap, parent ≤ child. The minimum is at the root; the entire array is not sorted.

Array formulas (0-based)

Parent: ⌊(i−1)/2⌋ · Left: 2i+1 · Right: 2i+2

Insert and extract minimum

Insertion bubbles upward. Extract-min moves the last item to the root and sifts it downward.

HEAPS · 02

Binomial heaps

A binomial heap is a collection of binomial trees with at most one tree of each degree. Its structure makes heap union efficient.

Binomial tree Bₖ

B₀ is a single node. Bₖ is formed by linking two Bₖ₋₁ trees. It has 2ᵏ nodes, height k, and root degree k.

Forest resembles binary bits

A heap with n nodes has a tree for each set bit in n's binary representation. Example: 13 = 8 + 4 + 1 → B₃, B₂, B₀.

Link operation

Compare two equal-degree roots; make the larger root a child of the smaller. This is analogous to carrying in binary addition.

TRY IT

Insert and link equal-degree trees

Each insert adds B₀. Collisions carry upward by linking roots.

● INTERACTIVE
Insert 13 values to see degrees B₃, B₂ and B₀.
Typical bounds: find-min O(log n) (or O(1) with a maintained pointer), insert O(log n), union O(log n), decrease-key O(log n), extract-min O(log n). A single insert may trigger links; the amortized intuition is similar to binary-counter carries.
HEAPS · 03

Fibonacci heaps

A Fibonacci heap is a lazy forest of heap-ordered trees. It postpones structural work during insert and meld, then consolidates trees during extract-min.

Lazy insertion

Add a singleton root to the root list and update the min pointer. No tree linking is required immediately.

Consolidation

After removing the minimum, promote its children, then repeatedly link roots with equal degree until root degrees are unique.

Amortized analysis

Potential Φ = number of roots + 2 × number of marked nodes. Cheap operations leave potential that pays for later work.

TRY IT

Lazy insert vs extract-min consolidation

Insertions keep separate roots. Extract-min promotes children and consolidates equal degrees.

● INTERACTIVE
Try inserts 16, 5, 24, 8. Root list grows without links. Extract min to consolidate.

HEAP APPLICATIONS

Where priority queues appear

01

Graph algorithms

Dijkstra's shortest-path and Prim's minimum spanning tree repeatedly select the next minimum-weight candidate. Decrease-key matters in implementations that update priorities in place.

02

Scheduling and simulation

Operating systems, event simulation, and task schedulers repeatedly choose the next event or highest-priority task.

03

Top-k and merging

Keep the best k candidates, or merge k already-sorted streams by repeatedly taking the smallest current head.

04

Heap sort

Build a heap, then repeatedly remove the root to produce sorted order in O(n log n) time and O(1) auxiliary array space in the in-place form.

01

Need sorted range results?

Choose a B+ tree: descend to the first leaf and follow leaf links.

02

Need exact priority removal?

Choose a binary heap for a compact, straightforward priority queue.

03

Need frequent heap meld?

Binomial or Fibonacci heaps support union more directly than a binary heap.

04

Need frequent decrease-key?

Fibonacci heaps offer O(1) amortized decrease-key, at the cost of complexity.

Comparison caution: These are asymptotic bounds, not benchmark promises. Constants, memory layout, cache behavior, key distribution, workload mix, and storage media affect observed speed.
